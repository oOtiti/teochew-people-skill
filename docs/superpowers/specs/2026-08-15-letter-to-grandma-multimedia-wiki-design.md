# 《给阿嬷的情书》多媒体 Wiki 专题设计

**状态：** 方向已确认；书面规格待用户复核

**日期：** 2026-08-15

**目标：** 以电影为入口，建立可追溯、可生产、可审校的潮汕文化图文专题与视频素材入库链路

## 1. 背景与现状

TEOCHEW PEOPLE 已经具备 raw 来源卡、主题页、分类索引、研究与演进操作，以及文章和短视频示例。当前与《给阿嬷的情书》直接相关的公共知识主要包括：

- 2 条电影专属 raw 来源：国家电影局活动报道和《羊城晚报》上映前报道。
- 1 个 current-event topic：记录 2026 年上映、展映和座谈节点。
- 与影片文化表达可关联的侨批、潮汕话、侨乡、海外潮人社群等长期主题。

现有资料足以证明部分公开传播节点，但不足以支持一篇细节丰富、图文并茂且适合继续派生视频的文化专题。README 当前展示的文章和视频示例也仍以拜老爷／营老爷为主题，尚未体现多种素材汇入同一 Wiki 的能力。

## 2. 目标

本次升级要完成四件彼此连通的工作：

1. 精选并补充能够支持电影事实、侨批、潮语、家庭记忆、跨海迁徙和影像表达的高质量来源。
2. 扩充电影事件页、相关长期主题与视频素材入库指南。
3. 产出一篇图文专题、两种时长的短视频脚本和一份视频转 Wiki 演示。
4. 将新内容纳入 README、Wiki 分类索引、场景细节索引、Skill 路由与发布包。

最终呈现应同时服务阅读和生产：普通读者看到的是有叙事、有画面、有来源的专题；作者和视频团队还可以继续追到 raw、时间码、镜头依据和权利状态。

## 3. 非目标

- 不写成片方宣传稿、剧情复述或无来源的价值判断。
- 不把电影情节、道具或主创自述直接当作潮汕历史事实。
- 不以转载数量代替来源质量，也不为了凑满篇幅降低 A／B 来源门槛。
- 不提交未经许可的海报、剧照、电影片段、台词、音乐或完整视频转录。
- 不把用户提供的家庭经历默认写入公共仓库。
- 不改动现有简洁的 `TEOCHEW PEOPLE` 主英雄图；电影专题只在英雄图下方获得清晰入口。

## 4. 方案选择

评估了三种方向：

### 4.1 电影档案页

聚焦上映、主创、取景、展映和评价。实现较快，但文化纵深有限，也难以展示 Wiki 对写作和视频生产的独特价值。

### 4.2 文化专题叙事

以电影为入口，进入侨批、潮语、阿嬷、汕潮揭与东南亚家庭记忆；再回到电影如何选择和重构这些材料。阅读体验和证据链能够同时成立。

### 4.3 多媒体生产实验室

聚焦视频登记、转录、时间码、镜头证据和脚本模板。链路完整，但若直接作为首页主内容，容易削弱文章的情感与阅读节奏。

**采用方案：** 以 4.2 为专题正文，吸收 4.3 作为底层生产能力。电影只是入口，真实文化材料是主体；工具链藏在来源卡、证据表和制作附录中，不打断主要叙事。

## 5. 编辑定位

专题暂定标题：

> 一封信，穿过海：《给阿嬷的情书》与潮汕家庭记忆

内容比例作为编辑约束而非机械字数配额：

- 约 30%：电影已公开、可核验的事实和主创自述。
- 约 50%：侨批、潮语、家庭称谓、跨海迁徙和地方空间。
- 约 20%：电影材料如何被选择、重构，以及写作与视频如何继续使用这些证据。

全文必须持续区分：

- `source_detail`：来源直接支持的事实和细节。
- `attributed_statement`：必须归于主创、受访者或研究者的说法。
- `synthesis`：编辑基于多个来源形成的有限综合判断。
- `editorial_visual`：地图、时间线、构图和原创示意，不冒充历史现场。
- `unknown`：公开材料不能回答、需要用户或当地知情者复核的内容。

## 6. 来源研究设计

### 6.1 覆盖矩阵

研究不以固定条数为验收目标，而以以下证据面是否被可靠覆盖为准：

| 证据面 | 优先来源 | 主要用途 |
| --- | --- | --- |
| 上映、展映、座谈、主创与制作节点 | 国家电影主管部门、片方／出品方正式渠道、具名主创访谈 | 电影事实与时间线 |
| 影片使用潮语、侨批和取景地的创作选择 | 主创建制材料、正式采访、活动实录 | 归因后的创作说明 |
| 侨批的档案属性与历史范围 | 档案馆、博物馆、政府文化机构、学术原始研究 | 区分真实档案与电影叙事装置 |
| 潮语及地方口音 | 方言研究、地方志、权威文化机构 | 声音、地域与表达边界 |
| 汕头、潮州、揭阳和东南亚联系 | 方志、侨史、档案与学术研究 | 地图与跨海家庭背景 |
| 当代传播与受众反应 | 可核时间点的正式数据、具名报道 | 只写对应日期的传播状态 |
| 图片与视频 | 原发布者、公共领域／开放许可平台、明确授权的用户素材 | 视觉、时间码和镜头证据 |

每个章节的稳定核心事实至少由 1 条直接 A 来源或 2 条相互独立且直接的 B 来源支持。若达不到门槛，就收缩论断或标记 `unknown`，不以 C 级故事性材料补强定义、起源或普遍性。

### 6.2 准入与拒绝

- 每个候选来源先进入 `raw/source-review.md`，记录 Admit、Reject 或 defer 及理由。
- 同源转载只保留最接近原发布者、内容可复核的一份作为 canonical。
- 搜索摘要、百科、营销软文、无署名转载和缺少发布日期的页面只用于找线索。
- 影片公开材料能证明“主创如何表达”，不能自动证明影片中的历史细节。
- 当前票房、发行、活动和版权窗口必须在使用当日实时核验，并保留截止时间。

### 6.3 用户背景

用户提供的真实家庭或地方背景默认进入项目本地 overlay，作为 review 依据，不自动成为公共事实。只有用户明确授权公开、确认署名／匿名方式并完成地域限定后，才可作为 C 级生活经验进入公共 raw；否则只用于指出现有专题需要修正的地方。

## 7. Topic 与 Skill 结构

### 7.1 必做更新

- 扩充 `wiki/current-events/给阿嬷的情书-2026.md`：增加来源覆盖、电影／历史边界、视觉素材状态和后续传播核验项。
- 加强 `wiki/society-diaspora/侨批.md`、`wiki/arts-language/潮汕话.md`、侨乡与海外社群页面之间的桥接，但不为电影改写稳定定义。
- 更新 `wiki/guides/场景细节索引.md` 和 `wiki/guides/短视频口播与分镜.md`，加入电影专题入口与媒体证据字段。
- 新增视频素材转 Wiki 的操作说明，并从 `SKILL.md` 和 ingest/query 路由到该说明。

### 7.2 条件性新 Topic

只有研究达到稳定来源门槛时，才新增“潮语电影与地方影像表达”一类长期主题。若公开资料只够说明《给阿嬷的情书》这个个案，则所有结论留在电影事件页，不制造一个看似代表长期趋势的新主题。

## 8. 图文专题结构

专题保存为独立示范文章，并从 README 首页入口、电影事件页和 Wiki 索引可达。正文预计 3000—5000 字，采用以下章节：

1. **一封信，为何从阿嬷开始**：用电影公开事实建立叙事入口，不剧透式复述剧情。
2. **侨批不是电影道具**：说明档案的真实属性、可证明内容和历史边界。
3. **家如何成为一种声音**：讨论潮语与地方口音，但不把单一口音写成全潮汕统一声音。
4. **三座城市与一条跨海路线**：以地图梳理取景地和东南亚联系，明确取景不等于完整代表。
5. **电影如何重构真实**：把电影画面、主创自述、档案事实和编辑分析分层。
6. **仍需当地人回答的部分**：集中列出家庭称谓、生活细节、年代差异和用户 review 项。

每一重要段落应能追到 topic/raw ID；文末提供证据表、权利说明和需要继续核验的问题。

## 9. 视觉系统与素材权利

### 9.1 首页

保留现有 `TEOCHEW PEOPLE` 英雄图和简洁大字。紧随项目简介增加一个电影专题卡片，包含专题标题、简短引文、一张原创或明确授权的预览图，以及文章和视频脚本入口。

### 9.2 专题视觉

目标配置为 6—8 个视觉单元：

- 1 张专题头图：原创编辑插画，不使用演员肖像或仿制电影海报。
- 1 条电影研究／上映／展映时间线。
- 1 张汕头、潮州、揭阳与东南亚联系示意地图。
- 1 组侨批对象图卡；只有具备可复用许可的档案图片才嵌入，否则使用原创结构图并链接原馆藏。
- 1 张“电影表达／历史证据／未知边界”分层图。
- 1—3 张来源明确的文化参考视觉或原创示意图。

### 9.3 素材分类

每项视觉必须属于且标明以下一种：

1. `official_or_licensed`：官方提供且许可允许，或已取得明确授权，可随仓库分发。
2. `link_only`：可作为研究和查看入口，但不能复制进仓库或重新发布。
3. `editorial_original`：项目原创地图、时间线、图表或 AI 辅助生成示意，必须标注非历史照片、非电影剧照。

本地素材应有清单，至少记录 `asset_id`、类型、创建者／来源 URL、许可或授权状态、用途、alt 文本和核验日期。远程图片不直接热链；不能确认权利时只给文字链接。

### 9.4 英歌舞史诗展示图

项目首页在现有 `TEOCHEW PEOPLE` 英雄图之后增加第二张横向大图，用于展示潮汕人的生命力与群体风采。画面以英歌舞表演者为明确主体：动作有力量、人物从大背景中脱出，远景保留山海、街巷、古厝屋脊或人群形成的空间纵深，但不让背景压过人物。

该图必须满足：

- 使用图像生成工具创作无文字的原创编辑视觉，不仿制具体摄影作品、电影画面或现有队伍宣传照。
- 不生成可识别的真实人物、影视演员、具体队伍标识、商标或活动年份，不把画面冒充某次真实演出。
- 服装、脸谱、木槌、动作和队形先回到准入来源核对；无法确认的细节收缩为不具队伍身份的编辑表达。
- 使用深夜海青、矿物朱红、灯火金和盐白延续现有视觉系统；主体高对比，横向 16:9 构图，同时保留中央 4:5 与 1:1 裁切安全区。
- 首页以带说明的效果展示模块呈现，alt 与图注明确写“原创编辑视觉／非具体演出现场”；不得把一支队伍或一个地区写成全体潮汕人的唯一代表。
- 原始生成结果、最终裁切和素材清单均进入权利与制作审计；只有最终导出图进入公开发布包。

## 10. 视频演示

### 10.1 60 秒版本

结构为：电影入口 → 侨批不是道具 → 潮语与跨海家庭 → 电影和历史的边界 → 来源卡。适合社交平台，但每个事实镜头仍保留 source ID。

### 10.2 约 3 分钟版本

沿用专题六章中的主要线索，增加地图、档案和主创自述的区分。脚本需包含口播、时间码、镜头、声音、来源、权利、现场确认和安全字段。

### 10.3 演示边界

- 没有片方授权时，不使用电影镜头、海报、台词和音乐。
- 可以使用标题卡、原创地图、来源图卡和自制／获授权空镜。
- 不用别地素材冒充影片取景地，不安排演员重演家庭或宗教实践。

## 11. 视频素材转 Wiki 链路

```text
候选视频
  → 来源与权利登记
  → 必要范围的带时间码转录
  → 区分旁白／采访／字幕／画面观察
  → 逐条 claim + speaker + timecode + confidence
  → raw 来源卡与媒体证据表
  → 合并或新建 topic
  → 派生文章、口播和分镜
```

实施约束：

- 不默认下载或提交原视频二进制文件。
- 完整转录可能同样受版权保护；公共仓库只保留必要短摘、时间码和准确转述，除非许可允许完整保存。
- 画面中出现某个物件或动作，只能证明“该视频在该时间码呈现了它”；不能单凭画面推断起源、普遍做法或人物身份。
- 视频说话者、发布者和拍摄者可能不同，三个责任主体分别记录。
- 自动转录必须抽样回听；潮语、人名、地名和专有名词未经人工核对不得进入稳定 topic。
- 权利不明、删除或地区受限时保留状态和最后核验日，相关 claim 降级或标记不可复核。

首个演示只选择 1 条原发布者清楚、可在线复核的公开视频，完整走完上述链路；它用来验证方法，不承担整篇专题的全部证据。

## 12. Review 交付顺序

实施分成两个内容关口：

### 12.1 背景 review 包

先提交给用户：

- 候选来源清单及 Admit／Reject 理由。
- 各来源能证明和不能证明的内容。
- 文章详细大纲。
- 开头、侨批段、潮语段和“仍需当地人回答”段的样稿。
- 拟用视觉清单及权利状态。
- 60 秒和 3 分钟脚本梗概。

此时明确标出需要用户核对的家庭称谓、地方生活细节和时代背景。用户反馈先进入本地 review 记录；是否公开另行确认。

### 12.2 最终整合

用户确认背景后，再完成全文、视觉、脚本、视频入库演示、topic 合并与首页入口。若用户背景与公共来源冲突，则并列呈现或收缩表达，不静默覆盖公共事实。

## 13. 仓库集成

预计涉及以下公开区域；确切文件名在实施计划中固定：

- `skills/teochew-people-skill/raw/`：新增通过准入的来源卡和媒体证据记录。
- `skills/teochew-people-skill/wiki/`：更新电影事件页、长期主题和制作指南。
- `skills/teochew-people-skill/operations/`：补充媒体 ingest 路径。
- `skills/teochew-people-skill/SKILL.md`：增加图文专题和视频来源路由。
- `examples/`：新增电影图文专题、短视频脚本和视频转 Wiki 演示。
- `assets/`：仅放原创或明确可分发的专题视觉及权利清单。
- `README.md`：在英雄图下增加专题入口，不修改主英雄图文案。

“纳入 Wiki”在实现上意味着主题页、相关页面与分类索引均可达，raw 和 topic 可双向追踪，发布包包含所需公开文件；面向用户的产品文案不宣称内容经过神秘的“编译”。

## 14. 校验与测试

### 14.1 结构与证据

- 所有新增 topic 的 `source_ids` 均存在且已准入。
- 文章重要事实能够回溯 raw，归因、自有综合和未知状态清楚。
- 新增媒体记录的 URL、发布者、日期、媒体类型、时间码范围和权利状态完整。
- 电影事实、主创说法和历史事实没有互相替代。
- 新增索引无 stale、orphan 或断链。

### 14.2 素材与版权

- 所有本地视觉均有素材清单、alt 和可分发依据。
- `link_only` 素材不会进入 npm 包，也不会以远程图片热链嵌入。
- 原视频、完整电影转录、剧照、海报、台词和音乐不会误入包内容。
- `npm pack --dry-run` 精确审计新增文件。

### 14.3 内容生产

- 60 秒和 3 分钟脚本逐镜含来源和权利字段。
- 视频演示的每条 claim 能追到时间码或明确标为编辑结构。
- 文章在桌面和移动宽度下检查图片裁切、图注、alt、表格和链接。
- README 入口、专题内链、Wiki 索引和 Skill 路由均有效。

### 14.4 回归

完成现有 `wiki:index:check`、`wiki:lint`、`npm test`、`pack:check` 和 `git diff --check`，并增加针对媒体字段、素材清单和专题引用的测试。既有拜老爷／营老爷、个性化 vault 和安装器行为不得回退。

## 15. 验收标准

- 精选来源覆盖电影事实、侨批、潮语、地理／海外联系和素材权利，拒绝理由可审计。
- 完成一篇 3000—5000 字、6—8 个视觉单元的图文专题。
- 完成 60 秒和约 3 分钟两个视频脚本及制作表。
- 用一条公开视频完成“登记—时间码—claim—raw—topic—派生内容”的可复查演示。
