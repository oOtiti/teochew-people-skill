# Lint：结构与证据审查

## 触发条件

在公共语料或工具变化后、发布前，或索引、链接、证据状态出现异常时使用。

## 输入

skill 根目录、当前生成索引、变更文件，以及必要时指定的当前日期。

## 有序步骤

1. 运行 wiki lint，检查 frontmatter、唯一 ID、来源层级、source_ids、related、证据门槛和 freshness。
2. 运行 index check，确认 raw 与 wiki 索引由当前语料确定性生成。
3. 将问题分为安全机械修复与内容冲突：排序、过期索引和无歧义路径可安全修复；来源冲突、层级判断、事实改写与隐私归属必须人工判断。
4. 安全修复可重建索引或改正明确链接；内容冲突转 research／evolve，不自动选边。
5. 串行复跑索引、lint 与发布验证；有公共内容变化时追加 wiki-log。

## 写入边界

Lint 只可自动写确定性的索引和无争议的链接修正。不得自动改变文化论断、证据层级、地方范围或 private overlay。公共索引和日志更新必须串行。

## 失败处理

结构错误输出文件与错误码并返回非零；内容冲突保持原文不动，记录双方证据并升级处理。

## 完成检查

lint 零错误、index check 通过、重复 ID 与断链清零、陈旧页已更新或明确保留为待研究状态，且没有把内容判断伪装成机械修复。
